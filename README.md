# Quantum Radiophotovoltaic Converter Benchmark

QAOA design-selection benchmark for quantum radiophotovoltaic converter optimization under physical, manufacturing, and cost constraints.

This project was developed for Qiskit Fall Fest 2026 at the University of Ottawa.

---

## 1. Problem and goal

The project studies whether the Quantum Approximate Optimization Algorithm (QAOA) can bias sampling toward high-quality and physically feasible converter designs selected from a small materials catalogue.

Each candidate design combines:

- one absorber material;
- one surface geometry;
- one passivation option.

The catalogue contains:

\[
4 \times 4 \times 4 = 64
\]

possible designs.

Each design is evaluated using a frozen physics-based score table containing lifetime-averaged conversion efficiency, cost, process compatibility, and related physical quantities.

The optimization is subject to a module-cost budget of:

\[
51.0\ \text{USD/m}^2.
\]

The main question is:

> Can QAOA concentrate probability on the best feasible converter designs, and how does its behaviour change between ideal simulation, backend-derived noisy simulation, and real IBM Quantum hardware?

Because the problem contains only 64 states, exact classical enumeration is practical and is used as the ground-truth solver. The project therefore does **not** claim quantum advantage.

Instead, the small problem size allows every stage of the quantum workflow to be checked against the exact optimum.

### Success criteria

The main success criteria are:

- recover the same optimum identified by exact classical enumeration;
- measure the probability of sampling the best feasible design, `p(best)`;
- measure the fraction of samples satisfying all constraints;
- measure top-ranked design probabilities and mean feasible quality;
- compare QAOA against classical reference methods;
- evaluate the same frozen QAOA solutions under ideal, noisy, and real-hardware execution;
- record circuit depth, two-qubit gate count, shots, seeds, backend, software versions, and IBM job metadata for reproducibility.

## 2. Data and assumptions

### 2.1 Design catalogue

The optimization uses the frozen table:

[`data/scores.json`](https://github.com/t1mane/The_winners_QFF2026_uottawa/blob/main/data/scores.json)

The score table is generated by:

`src/physics.py`

from:

- [`data/catalogue.json`](https://github.com/t1mane/The_winners_QFF2026_uottawa/blob/main/data/catalogue.json)
- `data/am15g.csv`
- the physical assumptions documented in [`docs/assumptions.md`](https://github.com/t1mane/The_winners_QFF2026_uottawa/blob/main/docs/assumptions.md)

To regenerate the table when all source data are available:

```bash
python src/physics.py
```

Detailed parameter provenance, physical assumptions, units, and source citations are kept in `data/catalogue.json` and `docs/assumptions.md`.

The optimization code does not refit or alter the physical parameters. It reads the frozen score table.

### 2.2 Design space

Each of the 64 states represents one complete design:

- 4 absorber materials;
- 4 surface geometries;
- 4 passivation options, including no passivation.

At the selected budget:

| Count | Meaning | Number |
|---|---|---:|
| Categorical designs | All material / geometry / passivation combinations | 64 |
| Process-compatible | Passivation process is within the absorber temperature limit | 48 |
| Within budget | Cost ≤ 51.0 USD/m² | 15 |
| Feasible for optimization | Process-compatible and within budget | 15 |

The 16 process-incompatible designs are also above the selected budget, so the final feasible set contains exactly 15 designs.

A design exactly on the budget boundary is allowed. For example, c-Si / micro-pyramids / thermal SiO₂ costs 51.0 USD/m² and remains feasible.

### 2.3 Physical quantities

Efficiency is represented as the fraction of incident energy converted to electrical energy and is averaged over the 25-year service life used by the physics model.

Cost is expressed in USD per square metre of module using the cost basis stored in the catalogue.

These values are model outputs. They should not be interpreted as measured outdoor module performance.

### 2.4 Reproducibility of the data

The saved classical results include SHA-256 hashes of the score and catalogue files.

Line endings are normalized from Windows CRLF to LF before hashing so the same data produce the same hash across operating systems.

The saved classical reference was originally produced with Python 3.9.6 and NumPy 2.0.2 on macOS. The important design identities, query counts, and probabilities were reproduced in later environments, including the final Qiskit environment used for this project.

## 3. Approach

The project combines a physical score model, a six-qubit encoding, classical reference methods, QAOA simulation, backend-derived noise simulation, and real IBM Quantum execution.

The main workflow is:

```text
physical data
     ↓
scores.json
     ↓
64 encoded candidate designs
     ↓
classical exact optimum + baselines
     ↓
diagonal QAOA cost Hamiltonian
     ↓
QAOA parameter optimization
     ↓
ideal simulation
     ↓
backend-derived noisy simulation
     ↓
real IBM Quantum hardware
     ↓
compare probabilities, feasibility and resources
```

## 4. Six-qubit encoding

`src/encoding.py` maps each design to six binary variables.

The bit layout is:

```text
bitstring = material(2) | geometry(2) | passivation(2)
```

The state index is:

\[
s =
16(\text{material})
+
4(\text{geometry})
+
\text{passivation}.
\]

Every six-bit value therefore maps to one of the 64 catalogue rows.

For example:

```text
000111
```

decodes to:

- material 0: c-Si;
- geometry 1: micro-pyramids;
- passivation 3: Al₂O₃ deposited by ALD.

Qiskit count strings are decoded directly with:

```python
int(bitstring, 2)
```

The leftmost bit is the most significant bit.

`tests/test_encoding.py` verifies:

- encoding and decoding of all 64 states;
- agreement with the physics-design parser;
- feasibility values;
- reconstruction of the complete diagonal cost function;
- agreement between the encoded cost vector and the Qiskit Hamiltonian.

## 5. Score and optimization Hamiltonian

Among the feasible designs, efficiency is normalized as:

\[
r =
\frac{
\eta-\eta_{\min,\mathrm{feasible}}
}{
\eta_{\max,\mathrm{feasible}}
-
\eta_{\min,\mathrm{feasible}}
}.
\]

Therefore, for the best feasible design:

\[
r=1.
\]

For this catalogue, feasible efficiencies range from:

\[
0.117442
\]

to:

\[
0.261381.
\]

The QAOA cost assigned to each computational-basis state is:

\[
E =
-r
+
M\,I(\text{infeasible}),
\]

where:

- \(r\) is the normalized efficiency;
- \(M\) is the constraint penalty;
- \(I(\text{infeasible})=1\) for an infeasible design and 0 otherwise.

The Hamiltonian implementation is in:

`src/hamiltonian.py`

The identity contribution is retained in the diagonal energy.

The training scale is based on the feasible minimum and maximum efficiencies. A second unit-interval scale is used only for checking the penalty behaviour.

## 7. Classical reference methods

`src/baselines.py` implements the classical reference methods.

These methods do not modify the score table.

### 7.1 Exact enumeration

Exact enumeration checks all 64 catalogue rows and selects the feasible design with the highest lifetime-averaged efficiency.

Ties are broken by:

1. lower cost;
2. lower state index.

The optimum is unique for the selected budget.

Exact enumeration is the ground truth for this small problem.

### 7.2 Uniform feasible sampling

Uniform sampling draws with replacement from the 15 feasible designs.

Sampling seeds are:

```text
11
22
33
```

Each classical random run uses:

```text
4096 draws
```

The probability of drawing the unique optimum at random from the feasible set is:

\[
\frac{1}{15}=0.066667.
\]

The probability of drawing one of the top three feasible designs is:

\[
\frac{3}{15}=0.20.
\]

### 7.3 Absorption-first greedy

The absorption-first heuristic ranks:

- materials using catalogue record efficiency;
- geometries using the optical proxy

\[
(1-\text{reflectance})\times\text{path enhancement};
\]

- passivations using surface-recombination information.

The algorithm returns the first feasible combination found using this ordering.

For the selected budget, it examines 24 candidates.

### 7.4 Coordinate greedy

Coordinate greedy starts from the lowest-index feasible design and makes one pass through:

1. material;
2. geometry;
3. passivation.

At each step it changes one category while keeping the others fixed and keeps the highest-efficiency feasible option.

The saved run uses 13 queries.

## 8. Evaluation metrics

`src/metrics.py` evaluates classical and quantum outputs using the same physical reference table.

The main metrics are:

| Metric | Definition |
|---|---|
| Feasible fraction / `p_feasible` | Fraction of outcomes satisfying all constraints |
| `p(best)` / `p_best` | Fraction of outcomes equal to the exact optimum |
| Optimum-hit rate | Fraction within \(10^{-9}\) efficiency of the exact optimum |
| Top-1 hit rate | Fraction producing the best feasible design |
| Top-3 hit rate / `p_top3` | Fraction producing one of the three highest-ranked feasible designs |
| Chance over all bitstrings | \(1/64 = 0.015625\) |
| Chance over feasible designs | \(1/15 = 0.066667\) |
| Mean feasible score | Shot-weighted mean normalized score \(r\) over feasible outputs |
| Objective gap | \(1-r\) for the best feasible result observed |
| Efficiency gap | Exact optimum efficiency minus the best feasible sampled efficiency |

If a sample contains no feasible design, the feasible fraction is zero and quantities that require a feasible design are left undefined rather than being replaced with zero.

The penalty study evaluates:


```text

```

- `M = 0` fails to enforce the constraint and selects an over-budget design;

The simulator studies:

```text

```


The final three frozen parameter sets are evaluated under:

1. ideal simulation;
2. backend-derived noisy simulation;
3. real `ibm_quebec` hardware.

The QAOA parameters are not retrained between these three conditions.

This isolates the effect of moving from an ideal model to modeled noise and then to physical hardware.

### 13.9 Sampling uncertainty

The ideal probabilities are calculated from the simulator distribution and therefore do not contain finite-shot uncertainty.

The noisy and hardware experiments use 2048 shots.

For probabilities near 0.5, the binomial standard error at 2048 shots is approximately one percentage point.

For the observed `p(best)` values, the one-standard-deviation sampling uncertainty is approximately 0.4–0.5 percentage points.

Approximate 95% binomial intervals are therefore on the order of:

- ±2 percentage points for feasible fraction;
- ±0.8 to ±1.0 percentage points for `p(best)`.

These shot-noise uncertainties do not include systematic device errors.

## 15. Discussion and limitations

### 15.1 Classical search is better for this problem size

The current catalogue contains only 64 designs.

A classical computer can enumerate every possibility exactly in well under a millisecond.

Therefore, QAOA is not faster or more accurate than exact classical enumeration for this instance.

This project should not be interpreted as a demonstration of quantum advantage.

The small search space was deliberately useful because it provides a known classical ground truth against which the quantum workflow can be validated.

### 15.2 What QAOA demonstrates here

The useful question is not whether QAOA beats the exact 64-state search in runtime.

Instead, the experiment studies the probability distribution created by QAOA.

The ideal QAOA solution increases the probability of the exact optimum relative to uniform sampling over all 64 bitstrings.

It also produces a majority of feasible outcomes in ideal simulation.

This makes the instance useful as a controlled benchmark for studying the transition from ideal QAOA to noisy simulation and then real quantum hardware.

### 15.3 Hardware noise

Performance decreases from ideal simulation to noisy simulation and decreases further on real hardware.

For example, feasible probability falls from approximately:

```text
56.7% ideal
→ 50.1% noisy
→ 34% hardware
```

while `p(best)` falls approximately from:

```text
7.56% ideal
→ 5.9% noisy
→ 3.7–4.6% hardware
```

The final circuits have depth 830 and 287 two-qubit gates.

This makes them sensitive to physical gate errors, decoherence, readout error, calibration drift, and other device effects.

The backend-derived Aer noise model reproduces part of this degradation but does not perfectly reproduce the real device.

That difference is itself an experimental result.

### 15.4 Penalty choice is instance-specific

The observed penalty threshold is specific to the frozen score table and normalization.

A different catalogue or different cost budget could require a different penalty.

The value:

```text
M = 2
```

is safe for this instance but should not be treated as a universal QAOA penalty.

### 15.5 Model limitations

The converter efficiencies and costs are model values taken from the frozen score table.

They are not direct outdoor measurements of fabricated devices.

Changing:

- material parameters;
- degradation assumptions;
- process-compatibility limits;
- component prices;
- budget;
- service life;

can change the ranking.

The selected optimum therefore applies only to this defined model and constraint set.

### 15.6 Baseline limitations

Uniform feasible sampling intentionally samples only legal designs and therefore has feasible probability 1 by construction.

It is useful as a chance baseline for `p(best)` and top-k probability but is not directly equivalent to sampling the complete six-bit Hilbert space.

The two greedy methods are intentionally inexpensive heuristics and are not globally optimal methods.

Their failure to find the optimum illustrates the quality/query trade-off rather than a failure of classical computing in general.

### 15.7 Scaling

The present six-qubit experiment is intentionally small enough to validate exactly.

Increasing the number of binary decision variables causes the number of possible states to scale as:

\[
2^n.
\]

However, a larger state space alone does not demonstrate quantum advantage.

Larger future instances would also require manageable Hamiltonian structure and shallower circuits before useful hardware scaling could be expected.

## 16. Unsuccessful and negative results

Negative results are included because they affect the final interpretation.

### Penalty \(M=0\)

With no infeasibility penalty, the objective selects:

```text
001111
```

which has higher modeled efficiency but exceeds the cost budget.

Therefore, constraint penalties are necessary.

### Greedy baselines

Neither greedy baseline reaches the global optimum.

They save queries but return lower-ranked feasible designs.

### Real hardware degradation

Real IBM hardware produces lower `p(best)` and lower feasible probability than ideal and backend-derived noisy simulation.

This does not invalidate the experiment.

It shows the practical effect of current device noise on the chosen QAOA circuit.

### No quantum advantage

Exact enumeration remains dramatically faster and deterministic for the 64-state instance.

This is an expected and important result rather than a failure of the project.

## 17. Conclusions

Under the:

\[
51.0\ \text{USD/m}^2
\]

budget, the unique best feasible design in the frozen catalogue is:

```text
000111
c-Si / micro-pyramids / Al₂O₃ (ALD)
```

with:

```text
lifetime-averaged efficiency = 0.261381
cost                         = 50.0 USD/m²
```

Exact enumeration finds this optimum by checking all 64 designs.

The classical random-feasible baseline samples the optimum with the expected probability of approximately:

\[
1/15=6.67\%.
\]

The greedy methods use fewer queries but fail to reach the optimum.

The QAOA cost operator correctly reproduces the constrained optimum when a sufficient infeasibility penalty is used.

For the final:

```text
p = 1
M = 2
```

QAOA solutions, the three optimization seeds converge to very similar parameters.

The ideal QAOA distribution produces approximately:

```text
p(best)       ≈ 7.56%
p(feasible)   ≈ 56.7%
```

Backend-derived noise reduces performance to approximately:

```text
p(best)       ≈ 5.9%
p(feasible)   ≈ 50.1%
```

and real `ibm_quebec` execution produces approximately:

```text
p(best)       ≈ 3.7–4.6%
p(feasible)   ≈ 34%
```

The real device therefore shows substantial degradation relative to ideal simulation.

However, the same exact optimal design remains the target optimum throughout the classical, ideal, noisy, and real-hardware analysis.

For this small catalogue, classical exhaustive enumeration is the correct practical solver.

The contribution of the quantum experiment is an end-to-end and reproducible QAOA benchmark showing how a constrained engineering design problem can be encoded, optimized, simulated, noise-tested, and executed on real quantum hardware while remaining verifiable against exact classical ground truth.

### Future work

Useful extensions include:

- larger materials catalogues;
- additional engineering constraints;
- sensitivity analysis for different budgets;
- alternative encodings;
- lower-depth cost-Hamiltonian approximations;
- reduced two-qubit gate counts;
- error mitigation;
- larger multi-component design spaces;
- comparison with stronger classical optimization methods.

These are proposed extensions and were not required for the completed experiment.
